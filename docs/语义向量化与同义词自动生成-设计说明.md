# 语义向量化与同义词自动生成 — 设计说明

> 版本 v1.0 · 2026-07-29

---

## 一、背景与目标

本体库存储了水利行业的结构化知识，但各实体的 label / description 等语义字段目前没有被向量化，也没有系统化的同义词支撑，导致语义检索、问答路由等功能无法落地。

**目标**：

- 接入 DeepSeek LLM，为每个实体的语义字段自动生成同义词
- 接入 SiliconFlow BGE embedding，将实体语义文本和同义词向量化，写入向量库
- 覆盖 6 类本体实体，同义词本身也向量化
- SQLite 开发环境只生成同义词，跳过向量步骤；PostgreSQL 生产环境完整走全流程

---

## 二、实体覆盖范围

| entity_type | 数据表 | 语义字段 | parent_id 含义 |
|------------|-------|---------|--------------|
| `class` | `ont_class` | `api_name, display_name, rdfs_label, rdfs_comment, description` | — |
| `class_prop` | `ont_class_property` | `api_name, display_name, rdfs_label, rdfs_comment` | `class_id` |
| `link_type` | `ont_link_types` | `rdfs_label, rdfs_comment, l_display_name, r_display_name` | — |
| `shared_prop` | `ont_shared_properties` | `prop_code, rdfs_label, rdfs_comment` | — |
| `biz_category` | `ont_biz_category` | `category_code, rdfs_label, rdfs_comment, description` | `parent_id`（自关联） |
| `enum_item` | `ont_enum_items` | `code, api_name, label`（前缀拼上所属枚举类型 rdfs_label） | `enum_id` |

`biz_category` 通过 `ns_code` 字段绑定命名空间，是向量检索的**顶层路由维度**，优先保证语义质量。

`enum_item` 的 `ns_code` 经由 `ont_enum_types.category_code → ont_biz_category.ns_code` 两级关联取得。

## 三、同义词设计

### 3.1 存储表（`sys_synonym_dict`）

在原有字段基础上新增两列（Flyway V27 迁移）：

| 新增字段 | 类型 | 说明 |
|---------|------|------|
| `entity_type` | TEXT | 对应上表 entity_type 枚举值 |
| `entity_id` | TEXT | 对应各实体表的 id，支持反向追踪 |

原有字段说明：

| 字段 | 说明 |
|------|------|
| `word` | 主词，取实体的 `display_name` 或 `rdfs_label`（取第一个非空） |
| `synonyms` | JSON 数组，DeepSeek 返回 5-8 个中文同义词 |
| `domain` | `ns_code`（无时用 `entity_type` 兜底） |
| `source` | `'AI'`（区别于人工维护的 `'MANUAL'`） |
| `confidence` | `0.8` |

冲突处理：`ON CONFLICT(word, domain) DO UPDATE SET synonyms=..., update_time=...`

### 3.2 同义词生成 Prompt

```
system: 你是一个专业的水利行业本体专家。给定一个概念，输出5-8个中文同义词或近义词，
        严格返回JSON数组格式，不含任何解释或额外文字。示例：["水库","蓄水池","储水设施"]

user:   概念：{word}
        描述：{desc}
```

## 四、向量化设计

### 4.1 向量表（`ont_entity_embeddings`，PostgreSQL 专用）

```sql
CREATE TABLE ont_entity_embeddings (
    id            BIGSERIAL PRIMARY KEY,
    entity_type   VARCHAR(32) NOT NULL,   -- 见上表 + 'synonym'
    entity_id     TEXT NOT NULL,          -- 各实体表 id 或 sys_synonym_dict.id
    parent_id     TEXT,                   -- class_prop→class_id 等
    ns_code       TEXT,                   -- 用于命名空间分区检索
    source_text   TEXT NOT NULL,          -- 向量化的原始拼接文本
    embedding     vector(768) NOT NULL,
    version       BIGINT NOT NULL DEFAULT 1,
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(entity_type, entity_id)
);
-- 索引：ns_code（分区过滤）、entity_type（类型过滤）、HNSW（ANN 检索）
```

部署脚本：`deploy/ontology/setup-entity-embeddings.sql`（执行一次）

### 4.2 source_text 拼接规则

各字段非空才拼入，字段间空格分隔：

- **class**：`{api_name} {display_name} {rdfs_label} {rdfs_comment} {description}`
- **class_prop**：`{api_name} {display_name} {rdfs_label} {rdfs_comment}`
- **link_type**：`{rdfs_label} {rdfs_comment} {l_display_name} {r_display_name}`
- **shared_prop**：`{prop_code} {rdfs_label} {rdfs_comment}`
- **biz_category**：`{category_code} {rdfs_label} {rdfs_comment} {description}`
- **enum_item**：`{枚举类型rdfs_label} {code} {api_name} {label}`（枚举类型标签作语境前缀）
- **synonym**：`{word} {syn1} {syn2} ...`（整行同义词拼接）

### 4.3 Embedding 模型

| 配置 | 值 |
|------|---|
| 服务商 | SiliconFlow |
| 模型 | `BAAI/bge-base-zh-v1.5` |
| 维度 | 768（与现有 VectorConfig.dimension 一致） |
| API | `POST https://api.siliconflow.cn/v1/embeddings`（OpenAI 兼容格式） |

## 五、处理流程

```
POST /api/tool/synonym/generate  { entityType, entityId }
  │
  ├─ 1. 按 entityType 查对应表，取语义字段
  ├─ 2. 调 DeepSeekSynonymClient → 同义词 JSON 数组
  ├─ 3. upsert sys_synonym_dict（entity_type + entity_id 标记来源）
  ├─ 4. 是否 PostgreSQL?
  │     ├─ YES: 向量化 source_text → upsert ont_entity_embeddings (entity_type=实体类型)
  │     │       向量化同义词行     → upsert ont_entity_embeddings (entity_type='synonym')
  │     └─ NO:  跳过向量，仅写同义词（SQLite 开发环境）
  └─ 5. 返回 { synonyms, vectorized, skippedReason }
```

批量接口 `POST /api/tool/synonym/batch-generate { entityType, limit }` 内部分页循环调用单条流程。

## 七、API 接口

### 7.1 单条生成

```
POST /api/tool/synonym/generate
Content-Type: application/json

{ "entityType": "class", "entityId": "class-xxxxxxxx" }
```

响应：
```json
{
  "code": 200,
  "data": {
    "entityType": "class",
    "entityId": "class-xxx",
    "word": "水文站",
    "synonyms": ["流量监测站","水位站","测流断面"],
    "vectorized": true,
    "synonymId": "syn-xxx"
  }
}
```

### 7.2 批量生成

```
POST /api/tool/synonym/batch-generate
Content-Type: application/json

{ "entityType": "biz_category", "limit": 0 }
```

`limit=0` 表示全量。响应包含 `total / success / failed / skipped`。

### 7.3 状态查询

```
GET /api/tool/synonym/status
```

响应包含 `provider / model / vectorType / pgAvailable / embeddingDimension`。

## 八、配置说明

```yaml
# bontolink-admin application.yml
bontolink:
  embedding:
    provider: siliconflow       # mock（开发）/ siliconflow（生产）
  deepseek:
    api-key: ${DEEPSEEK_API_KEY}
    base-url: https://api.deepseek.com/v1/chat/completions
    model: deepseek-chat
  siliconflow:
    api-key: ${SILICONFLOW_API_KEY}
    base-url: https://api.siliconflow.cn/v1/embeddings
    model: BAAI/bge-base-zh-v1.5
    timeout-seconds: 30
```

开发环境设 `provider: mock` 可跳过 SiliconFlow 调用（仍会生成同义词）。
