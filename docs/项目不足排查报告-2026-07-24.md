## 二、中等问题（建议本迭代处理）

### 后端

- **测试覆盖为零**：全 backend 无一个 `src/test` 测试类，仅一个 curl 脚本 `test-semantic-expansion.sh`（4 个模块都声明了 spring-boot-starter-test 却无一测试）
- **参数校验整体缺失**：`@Valid/@NotBlank` 全项目 0 命中（validation starter 已引入未用）；31 个 Controller 普遍用 `Map<String,Object>` 接参
- **SQLite 与 PG schema 严重漂移**：SQLite 版 41 张表 0 索引、几乎无外键；PG 版 30+ 索引含 api_name 唯一索引 → SQLite 下可重复、全表扫描
- **异常处理不当**：多处 `catch{}` 空块、`System.err.println` 吞异常后继续；`e.getMessage()` 原样返回前端泄露内部信息
- **`@Transactional` 标在 Controller 上**（ClassMetaController.java:320,378），破坏分层
- **废弃代码未清理**：`backend-old/` 62 个文件仍被 git 跟踪（含旧 DebugSqlController、backend.log、startup.log、jar）；admin 源码混入异名包 `com.watf` 工具类（30+ 处 System.out.println）

### 前端

- **无 lint/test/typecheck 脚本**：eslint/stylelint 装了全套却无运行入口；两个前端零测试文件
- **依赖过旧/已废弃**：vite 5.x（EOL）、monaco-editor 0.33（2022）、@antv/g6 v4、eslint 8、vite-plugin-eslint（官方已废弃）、pnpm 8
- **dependencies 混放**：bk-analysis-maker 把 vue/element-plus/echarts 等运行时包全放 devDependencies，与 peerDependencies 大面积重复
- **构建产物误提交**：bk-analysis-maker 的 `dist/`（3.4MB）与 `stats.html` 已入库
- **无环境变量管理**：无 `.env.example`；vite 代理硬编码 `127.0.0.1:8088`；dev server `host:'::'` 局域网可达
- **超长单文件**：Category.vue 3079 行、EnumTypes.vue 2475 行、maker-presets.js 2459 行等 15+ 个 500+ 行文件
- **两套 UI 框架并存**：README 宣称"无 UI 框架自建 bl-*"，实际同时引入 element-plus + tdesign-vue-next；图表能力 also 两套（内嵌 bk-analysis-maker + 自带 echarts）

### 工程化

- **零 CI/CD**：无 workflows / Dockerfile / Jenkinsfile；`.github/` 里只有微软升级工具产物
- **tools/ 脚本硬编码他人机器路径**：`c:\beiktech-jyx\...`、`e:/aiproject/...`；且写死 8088 未适配双服务
- **无 LICENSE**
- **二进制办公文档入库**：`UI规范.docx`（已有同名 md，docx 无法 diff）

## 三、轻微问题（择机处理）

- 硬编码 Windows 绝对路径入代码：`ApiNameConflictChecker.java:15` → `c:/beiktech-jyx/...`

- 第三方组件库源码（bk-analysis-maker-vue3）混入业务仓，建议独立成仓
